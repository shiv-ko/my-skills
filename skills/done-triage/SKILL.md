# Done Triage

このVaultの `01_done/` に溜まったメモを1件ずつ処理し、`02_P`（技術的に有用な内容）・`05_所感`（自分の考え・所感）・`03_lib/読書メモ`（本の手動メモ）へ振り分けるスキル。`01_inbox/` は読み終えたら `01_done/` へ手動で移す運用になっているため、triageは `01_done/` のみを対象とし、`01_inbox/` には触れない。設計の背景は `docs/superpowers/specs/2026-07-20-inbox-triage-design.md` を参照（フォルダ名は当時の設計から変更されている点に注意。`01_P`は`02_P`、`00_inbox`は`01_inbox`/`01_done`に対応）。wikilinkやfrontmatterの正確な記法は [obsidian-skills/obsidian-markdown](https://github.com/kepano/obsidian-skills/tree/main/skills/obsidian-markdown) を一次情報として参照する。

## 手順

1. `01_done/` 配下の全Markdownファイルを列挙する（`.gitkeep`は除く）。すでに `triage: 要確認` が付いているファイルも対象に含める（再度読み直して判断できるようになっていないか確認する）。
2. ファイルごとに以下を **1件完結** で行う（1件の処理が終わってから次のファイルに進む。並行処理しない）。

   a. **発生源を判定する**
      - 本文が `[URL](` を含むリンクで始まり、`読んだ日:` という行がある → **記事由来**（ReadItLaterのテンプレート形式）
      - 本文中に書籍名・ページ番号・章タイトルなど、本を読んでいることを示す記述がある → **読書由来**
      - どちらにも当てはまらない → **学習由来**（興味を持って調べているメモ）
      - この判定はルールベースではなく、ファイルの中身を読んで総合的に判断すること

   b. **技術的に有用な内容と、自分の考え・所感を見分ける**
      - 技術的に有用な内容 = 客観的な事実・仕組みの説明・引用・コード例など
      - 自分の考え・所感 = 主観的な感想・評価・「〜と思った」「〜が気になる」のような一人称の考察
      - 所感が実質的に存在しない場合（多くの学習メモ・読書メモに該当）は所感の分離処理をスキップする

   c. **技術的に有用な内容を02_Pへ振り分ける**
      - `02_P` 配下に同一トピックの既存ノートがあるか、ファイル名・見出し・内容から検索する
      - 既存ノートがあれば、その本文に統合する（重複する説明は要約し、ユニークな情報は失わずマージする）
      - 既存ノートが無ければ、最も内容が近い `02_P` のサブフォルダに新規ノートとして作成する。適切なサブフォルダが無ければ新設してよい
      - 学習状況を追跡したい内容であれば、対象ノートのfrontmatterに `学習状況`（未着手/進行中/完了）・`希望度`（高/中/低）・`登録日`（処理を実行した日付）を設定する。記事を読んだだけで技術的な深掘りをしていないメモは `学習状況: 未着手` とする

   d. **自分の考え・所感があれば05_所感へ振り分ける（記事由来のときのみ発生しうる）**
      - `05_所感/` に、対応する02_Pノートと同じファイル名でノートを作成または追記する
      - 所感ノートの冒頭に、元記事のタイトル・URL（あれば）と、対応する02_Pノートへのリンク（`[[02_P/.../ファイル名]]`）を記載する
      - 対応する02_Pノート側にも `05_所感/ファイル名` へのリンクを追記し、相互リンクにする
      - このリンクは必ずフォルダ名を含めたパス形式（`[[02_P/.../ファイル名]]` など）で書くこと。`02_P` と `05_所感` に同名ファイルが存在する設計のため、`[[ファイル名]]` という省略形にするとObsidianがどちらのノートか解決できず曖昧になる（[obsidian-markdown](https://github.com/kepano/obsidian-skills/tree/main/skills/obsidian-markdown)のwikilink解決ルールを参照）

   e. **読書由来のメモは03_lib/読書メモへ振り分ける**
      - `03_lib/読書メモ/` に、書籍名をファイル名にしたノートを作成または追記する
      - Kindleハイライト（`03_lib/kindle_hilights/`）とは統合しない（別物として扱う）

   f. **振り分けが完了したら、01_done内の元ファイルを削除する**（02_P/05_所感/03_lib/読書メモへ内容を移し終えているため、01_done側にアーカイブとして残す必要はない。Vaultはgit管理下にあるため、誤りがあっても`git log`/`git show`で復元できる）

   g. **振り分け先を確信を持って判断できない場合**（内容が薄すぎる、複数トピックにまたがる、等）
      - ファイルを `01_done` に残したまま、frontmatterに `triage: 要確認` と、判断できなかった理由を `triage_memo:` に一言で追加する
      - `triage_memo` の値に半角コロン`:`など YAML の特殊文字が含まれる場合は、frontmatterが壊れないようダブルクォートで囲む（例: `triage_memo: "内容が薄い: 複数トピックにまたがる"`）
      - 削除しない

3. 全ファイルの処理が終わったら、以下の内容でレポートする:
   - 振り分けたファイル数と、それぞれの振り分け先（削除したことを含む）
   - `triage: 要確認` のまま残したファイルとその理由の一覧
   - `01_done` に残っているファイルの総数（未処理・要確認の合計）

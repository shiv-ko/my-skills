# Imozuruへの調査の引き継ぎ

ロードマップの調査には `imozuru` を使い、終了後にその根拠から学習順序を設計する。調査中はImozuruの方針どおり、原文の場所と引用を記録する。ロードマップへの整理は調査を区切ってから行う。

## 役割と保存先

- サブエージェントが使える場合は、調査の取りまとめを1体に任せる。親は学習目標・保存先・既存ノートを確認し、調査後のロードマップ設計とVaultの編集を担当する。使えない場合は親が調査を行う。
- 調査担当には、解決した `imozuru/SKILL.md` とこのファイルの絶対パスを渡し、最初に両方を読むよう指示する。親で読み込んだスキルが子に自動で渡るとは仮定しない。
- 調査担当がImozuruの検索役を使う場合は同時2本までとし、実行環境の同時実行枠にも収める。枠や機能が足りなければ、違う探し方の検索を順に行う。モデル名や製品固有のツール名は固定しない。
- 検索役を使わずに親や調査担当が検索を代行した周は、Imozuruの規則に従って飽和の計算に使わない。論点への原文の対応、周回上限、取得の限界、ユーザー指定の上限で終了を判定する。
- 調査担当の書き込み先は、親が指定した調査ディレクトリに限定する。Imozuruの既定は `~/research/<話題>/`。書き込めない場合は許可された作業ディレクトリ内に置き、実際の保存先を伝える。原文と調査記録はそこに保存し、既存ノートや進捗は親だけが編集する。

## 調査担当へ渡す内容

- テーマ、学習目標、現在の水準、目指す実例や成果物、制約。ユーザーの依頼にある条件を省略しない。
- 既存ロードマップを改訂する場合は、現在の段階・既知の知識・未解決の疑問。既存の原文や調査記録があれば渡し、必要な箇所を追加調査する。
- 調べる論点はImozuruの規則に沿って立てる。知見が集まる媒体に加え、中心概念、資料で裏付けられる前提関係、実践への適用、つまずく条件、原典と入門資料を、学習目標に合わせて含める。
- 保存先の絶対パスと、ユーザーが指定した時間・回数の上限。指定が無ければImozuruの終了条件に従い、根拠が付いた論点、未解決の論点、終了理由を記録する。

## 調査後に受け取るもの

Imozuruの `map.md`、`log.md`、`sources/`、検索・取得の記録、照合済みの `report.html` と `digest.html` の実在するパスを受け取る。作れなかったものは理由も受け取る。加えて、ロードマップに使う各概念・前提関係・資料について、次をたどれるようにする。

- 原文ファイルの行番号または動画の時刻、短い引用、元URL、確認日。
- 資料の版・公開日・対象読者と閲覧できたか。検索結果の抜粋しか見ていない情報は未確認とする。
- 資料が明示する前提関係と、エージェントが提案する学習順序の区別。異説や届かなかった資料、未解決の点。

親は返された原文の該当箇所を確認してから段階と参考資料を組む。原文の裏付けがない順序は学習上の提案として示し、未解決の論点を確認済みの前提にしない。マスターには学ぶための資料と調査記録へのリンクを置き、番号付きノートの初期内容は既存の規則どおり絞る。

Imozuru単独利用時の返事をそのまま最終回答にせず、親が完成したロードマップと保存先、調査上の未確認事項を案内する。調査だけを理由にRSS監視や定期実行を始めない。調査担当とその検索役が完了または停止したことを確認してから返す。

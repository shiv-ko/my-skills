# 差分を説明する

指定されたコード変更について、充実した対話的な解説を作成する。

次のセクションを含める。

- 背景: この変更に関係する既存システムを説明する。このために周辺コードを広く調査する。読み手がどの程度の前提知識を持つか分からないため、初心者向けの詳しい背景説明を含める。その部分は、すでに詳しい読者なら読み飛ばせるようにする。その後、変更に直接関係する、より焦点を絞った背景を説明する。
- 直感: コード変更の核となる直感を説明する。詳細をすべて説明するのではなく、本質を伝えることに重点を置く。簡単なサンプルデータを使った具体例を示す。図やダイアグラムを積極的に使う。
- コード: コードへの変更を大まかに案内する。理解しやすい単位と順序で変更をまとめる。
- クイズ: このPRに関する読み手の理解を確認する問題を5問作成する。難易度は中程度とし、PRの本質を実際に理解しなければ答えられない程度にする。ただし、ひっかけ問題にはしない。読み手が本当に理解できたかを自分で確認できるようにすることが目的である。対話的な選択式問題として提示し、選択肢をクリックすると正誤とフィードバックが表示されるようにする。

## 形式

- CSSとJavaScriptを内包した、自己完結型のHTMLファイルを1つ出力する。セクション見出しと目次を備えた縦長の1ページにする。最上位の構造にタブを使用しない。スマートフォンでも閲覧できる基本的なレスポンシブスタイルを用意する。ファイルはコードリポジトリ外にあるPC上の共通的な場所へ保存する。ファイルを時系列で並べやすく、バージョン管理の対象外に保てるよう、ファイル名は必ず当日の日付を`YYYY-MM-DD-`形式で先頭に付ける。例: `/tmp/2026-01-12-explanation-<slug>.html`
- Martin Kleppmannの文章のように、明快で流れがよく、読者を引き込む古典的な文体で書く。セクション間を滑らかにつなぐ。
- ダイアグラムについては、説明全体で再利用できる少数の図式ファミリーを選び、さまざまなケースの説明に使うことが望ましい。有用なダイアグラムの例:
  - UI変更を説明するための、ユーザーがアプリで目にするUIを大幅に簡略化した図。
  - コンポーネント間のデータフローまたは通信を示すシステム図。この図には必ずサンプルデータを含める。
- ASCIIアートのダイアグラムを使用しない。ダイアグラムには簡潔なHTMLデザインを、項目の列挙にはHTMLのリストを使用する。
- コードブロックには必ず`<pre>`タグを使用する。代わりに独自スタイルの`div`を使う場合は、CSSに必ず`white-space: pre-wrap`を指定する。ファイルを保存する前に、HTMLソース内の各コードブロックを確認し、そのCSSに`white-space: pre`または`pre-wrap`が含まれていることを確認する。
- 重要な概念や定義、注意すべきエッジケースなどにはコールアウトを使う。

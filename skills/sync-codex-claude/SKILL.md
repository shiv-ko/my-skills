# Codex と Claude Code を同期する

意図(intent)を同期する。ファイル名を同期するのではない。共有可能な内容を「ポータブルなコア」として扱い、製品固有の挙動は「アダプタ」として扱う。

ファイルを変更する前に [compatibility.md](references/compatibility.md) を読むこと。パスや現在の挙動が問題になる場合は、リンク先の公式ドキュメントを再確認すること。

## ワークフロー

1. スコープを決定する: プロジェクト、ユーザー、または両方。環境変数がデフォルトを上書きしている場合にそれを見逃さないよう、リポジトリのルート、現在の作業ディレクトリ、Codex のホーム、Claude の設定ディレクトリを特定する。
2. 両側を読み取り専用でインベントリ化する。instructions ファイル、skill ディレクトリ、ネストされたスコープ、agent 定義、シンボリックリンクを含める。シークレットを調べたり、設定を丸ごとコピーしたりしないこと。
3. セマンティックな単位で解析・比較する:
   - instructions とそのスコープ
   - skill の name、description、本文、同梱リソース
   - 製品固有の frontmatter
   - agent / subagent のプロンプトと能力(capabilities)
4. 各項目を `portable`(移植可能)、`codex-only`(Codex専用)、`claude-only`(Claude専用)、`convertible`(変換可能)、`conflict`(競合)のいずれかに分類する。
5. 所有権ポリシーを選択または確認する:
   - 共有プロジェクトの内容には、リポジトリが所有する中立的な source を優先する。
   - 個人的な内容はユーザースコープに保持する。
   - 更新日時だけで「勝者」を推測しない。
   - 両側が互換性のない形で変更されている場合、または信頼できる情報源が不明な場合はユーザーに確認する。
6. 作成・更新・変更なし・競合・スキップされた製品専用フィールドを含む dry-run(実行前確認)プランを提示する。重要な instructions の変更については、内容レベルの diff を含める。
7. ユーザーが許可した変更のみを適用する。無関係なファイルは保持し、アトミックまたは復元可能な書き込みを使用する。明示的に要求されない限り、差異のあるファイルを削除しないこと。
8. 両製品の結果的なレイアウトを検証する。重複した skill 名、壊れた相対リンク、無効な frontmatter、instructions の競合を確認する。片方の製品で表現できなかった挙動を報告する。

## 同期ルール

### Skills

- ポータブルな最小構成として `name` と `description`、および通常の Markdown instructions を使用する。
- 参照されている `scripts/`、`references/`、`assets/` は skill と一緒にコピーし、相対パスを維持する。
- Claude 専用の frontmatter を Codex 向けの `SKILL.md` にコピーしないこと。Claude アダプタ側に保持し、挙動上のギャップを説明する。
- Codex の `agents/openai.yaml` をポータブルな skill の挙動として扱わないこと。Codex 側専用として保持する。
- 同名の skill を明示的に検出する。Codex は両方のコピーを公開する可能性があるが、Claude には優先順位ルールがある。同一の衝突挙動になると仮定しないこと。
- 両方の実行環境がシンボリックリンクを解決できると分かっており、かつユーザーがそれを選んだ場合を除き、シンボリックリンクは避ける。移植性が重要な場合は、共有 source から生成したコピーを優先する。

### 永続的な指示

- 共有プロジェクトのガイダンスは `AGENTS.md` と `CLAUDE.md` の間で、バイト単位のコピーではなく意味でマッピングする。
- ツール固有のコマンド、権限モデル、hooks、呼び出し構文、UI instructions は、ラベル付きの製品セクションまたは別のアダプタファイルに保持する。
- ネストされたスコープを尊重する。ルートファイルとディレクトリローカルなファイルは異なる instructions レイヤーである。
- 常時読み込まれる instructions は簡潔に保ち、タスク固有の手順は skills に移す。

### エージェントとサブエージェント

- ポータブルなプロンプト、description、明確に同等な能力の制約のみを変換する。
- モデル名、ツール名、権限モード、hooks、メモリ、分離(isolation)、バックグラウンド実行、skill のプリロードは、同等性が確認されない限り製品固有として扱う。
- 変換の際に安全性の制約を弱めないこと。同等の表現ができない場合は、対象側をより制限的な状態に保ち、ギャップを報告する。

## 競合時の方針

以下の場合は書き込む前に停止する:

- 両側に、所有者が宣言されていない実質的に異なる編集が含まれている場合
- 変換によって実行可能な挙動、権限、hooks、安全性の制約が失われる場合
- 変換先のパスが無関係な skill や instructions ファイルを上書きしてしまう場合
- ユーザーレベルとプロジェクトレベルの内容が1つのスコープに統合されてしまう場合

競合ごとに、2つの source、セマンティックな差異、そしてユーザーに求める最小限の選択肢を示すこと。

## 出力

以下を報告する:

- 選択したスコープと source-of-truth ポリシー
- 同期したポータブルな項目
- 保持した製品固有のアダプタ
- 解決済みまたは未解決の競合
- 実施した検証
- 変更した正確なファイル

# フロー図をきれいな1枚画像にする

Mermaidや手描きの図は、記事に貼るとチープに見えることがある。自己完結HTML+SVGで図だけを描き、ヘッドレスChromeで高解像度PNGに書き出すと、Markdown記事にそのまま貼れる1枚画像になる。

## When to Use

- Markdown記事・ドキュメントに、フロー図/工程図を画像として埋め込みたい（Mermaidコードブロックや既存のスクショの差し替えを含む）
- 「カラフルすぎる」「もっとシンプルに」と図の見た目を直したい
- ブラウザのスクリーンショット/zoomツールで撮った図がぼやける・解像度が足りない

対象外: たとえ話つきの初心者向け説明ページは`/eli5`。データの可視化・グラフは`dataviz`スキル。本スキルは「説明文なし、図そのものだけ」を高品質な画像にする用途に絞る。

## 進め方

1. 自己完結HTMLを1つ書く（インラインCSS、外部依存なし）。中身はSVGの図だけ。タイトル・リード文・キャプション・たとえ話は入れない — 説明は記事の地の文に任せる。
2. 配色は下記のモノトーンパレットを既定にする。ユーザーが色を明示的に求めない限り、ノード種別は色でなく形・枠線・線種で区別する。
3. 完成イメージはヘッドレスChromeで高解像度書き出しする（後述のコマンド）。**ブラウザの screenshot/zoom ツールは長辺が868px前後に制限され、記事に貼るには粗すぎる。最終画像は必ずヘッドレス書き出しを使う。**
4. `sips -g pixelWidth -g pixelHeight <file>`で解像度を確認してから、リポジトリの画像ディレクトリ（例: `images/`）に保存する。
5. Markdownの画像リンクを差し替える（例: `![alt](./images/xxx.png)`）。古いMermaidブロックや旧画像は置き換える。
6. 作業用HTML・ローカルHTTPサーバーなど一時ファイルは後片付けする。最終的にリポジトリに残すのはPNGと更新後のMarkdownだけ。

## モノトーンパレット（既定）

```css
:root {
  --bg: #fbfaf7;         /* ページ背景 */
  --ink: #1f2430;        /* 文字・枠線・矢印 */
  --sub: #8b8f98;        /* 補助ラベル・ループ矢印 */
  --box-bg: #ffffff;     /* 処理ボックスの塗り */
  --diamond-bg: #eceae4; /* 分岐ノードの塗り */
}
```

処理ボックス = 白背景 + `var(--ink)` の枠線2.5px + 濃い文字。分岐ひし形 = 薄いグレー背景、同じ枠線。メインフローの矢印は実線`var(--ink)`。ループ・条件分岐の矢印は破線`var(--sub)`にして、色を増やさずに区別する。ユーザーが明示的に頼まない限り、これ以外の色は足さない。

## SVGレイアウトの型

- 横一列の`viewBox`にまとめる（例: `viewBox="0 0 2160 500"`）。ボックスは190×100・rx16程度、間隔60px、`<line>`+共通の矢印`<marker>`で結ぶ。
- 分岐は`<polygon>`のひし形。ラベルが長い場合は`<text>`を2行に分ける。
- ループバック矢印は直交パス（下がる→横に進む→上がる）でメイン行を避けて迂回させ、曲がり角付近に分岐ラベル（「はい」「いいえ」）を置く。
- `body{padding:30px} .wrap{width:100%} svg{display:block;width:100%;height:auto}`にしておくと、プレビューでもヘッドレス書き出しでも同じファイルがそのまま使える。

## 高解像度書き出し（このスキルの核心）

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --hide-scrollbars \
  --force-device-scale-factor=3 \
  --window-size=1200,320 \
  --screenshot="$(pwd)/out.png" \
  "file://$(pwd)/diagram.html"
```

- `--window-size`はCSS px。SVGの`viewBox`アスペクト比に合わせる（例: 2160×500 → 1200×280程度＋余白）。
- `--force-device-scale-factor=3`でラスタ解像度が3倍になる（1200×320のウィンドウ→3600×960のPNG）。荒さが気になれば4〜5に上げる。
- `CVDisplayLinkCreateWithCGDisplay failed`というエラーは無害なので無視してよい。
- 書き出し後は必ず`Read`ツールか`sips`で中身を確認し、要素の欠け・重なりがないかを見る。

## クイックリファレンス

| 手順 | コマンド/操作 |
| --- | --- |
| 図を書く | scratchpadに自己完結HTML+SVGを作成 |
| 簡易プレビュー（任意） | `python3 -m http.server`＋ブラウザ、または`Read`でHTMLを直接確認 |
| 高解像度書き出し | 上記のヘッドレスChromeコマンド |
| 解像度確認 | `sips -g pixelWidth -g pixelHeight <file>` |
| 保存 | `images/`など記事のディレクトリへ`cp` |
| 記事へ反映 | Markdownの画像リンクに差し替え、旧Mermaid/画像を削除 |
| 後片付け | 一時HTML・ローカルサーバーを停止・削除 |

## よくある失敗

- 最終画像をブラウザのscreenshot/zoomツールで済ませる → 記事幅で見るとぼやける。最終出力は必ずヘッドレス書き出しにする。
- 画像の中にタイトルやキャプション、たとえ話を入れてしまう → 記事本文の説明と二重になる。図だけにする。
- 「わかりやすさのため」とノードごとに色を割り振る → 全体がカラフルになり安っぽく見える。既定はモノトーン、色は頼まれたときだけ。
- 作業用のHTMLやhttp.serverプロセスを消し忘れる。
